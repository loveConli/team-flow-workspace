## 三个修复项（Roadmap 对应条目）

### ① P1-44 pre-tool-use-guard 路径化（死锁环1，根因级）

**现状**（team-flow/hooks/pre-tool-use-guard L105-116）：
Write/Edit/MultiEdit 仅当 state ∈ {approved-for-build, executing, debugging} 放行；
exploring/specifying/bridging/closing 一律 block——误伤工作流自身要求的产物写入
（exploring 写 architecture/*.md；specifying 写 proposal/specs/design/tasks；bridging 写 contract/test-matrix）。
matcher 只覆盖 Write/Edit/MultiEdit → LLM 用 Bash 绕过，写入彻底脱管。

**修复**：state 判定前增加路径判定——写入目标在活动 change 目录（含 .team-flow.yaml 的目录）内 → ALLOW（产物区）；
目录外 → 维持原状态门禁。防御契约不变（任何解析错误 → ALLOW，只有显式命中才 block）。

**测试**：新增 tests/lib/hook-pre-tool-use.test.mjs 矩阵：
exploring+change内→allow；exploring+change外→block；executing+change外→allow；
closing+change内→allow；无 yaml→allow；非 Write 工具→allow。

### ② P3-10 exploring→specifying 移除 artifacts-exist（死锁环2）

**现状**（team-flow/scripts/guard/guard.mjs L22）：
`'exploring:specifying': ['artifacts-exist', 'arch-design']`——四件规划产物是 spec-writer 在 specifying 阶段才生成的，鸡生蛋。
产物齐全性由 `'specifying:bridging': ['artifacts-exist', 'schema-valid']` 已保障。

**修复**：改为 `['arch-design']`。

**测试更新**：
- tests/lib/guard.test.mjs L68 "exploring→specifying requires artifacts-exist" → 改断言 arch-design
- tests/e2e/deterministic/guard-dimensions.test.mjs exploring→specifying 的 artifacts-exist 正/负向两例 → 迁移到 specifying→bridging 维度下
- state-machine.test.mjs 合法转换表不受影响（error=null 语义不变）

### ③ P2-40 hooks 版本同步（发版中断根治）

**现状**：hooks/session-start 硬编码 `PLUGIN_VERSION="x.y.z"` + 头部注释 `# vX.Y.Z:`；
`team-flow.mjs version` 同步脚本（scripts/lib/cmd-version.mjs）不覆盖 → 每次 `npm version` 链必在 check-versions 处中断（v0.27.1/v0.27.2/v0.32.0/v0.32.1 四次实证）。

**修复**：cmd-version.mjs 文件清单加入 hooks/session-start（两个模式：`# v<ver>:` 注释行 + `PLUGIN_VERSION="<ver>"`）。
check-version-consistency.mjs 已有该文件的检测（L70 extract `# v(\d+\.\d+\.\d+):`），同步后即通过。

**测试**：新增/扩展 cmd-version 测试——对临时 hook 副本跑同步，断言两处版本号更新。
