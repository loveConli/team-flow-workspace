交付物成熟

team-flow v0.33.0 已覆盖"模糊需求 → 交付归档"完整研发闭环，含代码级质量门禁（状态机 / hash 校验 / 测试矩阵 / 程序化测试证据），是内部 AI Coding 主力的可行底座。

策略：边迭代、边试点

试点团队当 beta 用户，feedback 反哺插件迭代；v1.0.0（10 月初）作为规模化分水岭——发布前只试点，发布后才全量推广。底层模型采用国内 API（如 DeepSeek），降低合规与网络风险。

价值主张

不是引入"AI 写代码工具"，而是把团队沉淀的 AI 研发方法论 + 质量门禁复制到全公司；需求到归档的每个环节有门禁、有产物、有知识复利，质量不滑坡。

三条纪律

  1. 产品级新需求必须走 orchestrator——唯一的规范化入口，不用个人对话方式直接写核心代码（否则产物无门禁 = 质量无保障）
  2. 门禁不放行 = 不完成——状态机、hash、测试矩阵、程序化证据是"完成"的定义，不是可绕过的建议
  3. 人工决策点不外包——DP-1（需求边界）、DP-3（契约批准）、DP-A（方案确认）、架构评审、代码合并审批，永远是人的责任

风险与依赖

风险 等级 对策
插件颠簸期稳定性 高 试点即 beta；升级窗口协商；v1.0.0 前不承诺规模化；关键修复优先
首批体验影响信任 高 陪跑兜底；问题快速修复；透明度（已知问题清单）；正向激励（首批 = 共建者）
安全合规 高 采用国内模型 API 降低跨境数据风险；密钥治理规范 + CI 扫描；代码外传白名单；MCP 权限最小化
成本 中 用量监控；上下文优化；评估订阅/API 计费组合
团队接受度 中 分层次培训；门禁是保护不是束缚；示范"AI 提高研发质量"而非"AI 替代人"
