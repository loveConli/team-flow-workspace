# SOP 使用说明 · LT 第二大脑管线

> 配套 `SKILL.md`。本文是**给你（LT）的操作手册**：什么时候跑、怎么跑、怎么审、怎么维护。
> 角色分工：你是**架构师 + 决策者**（定义逻辑、拍板留/弃、守深度思考）；AI(copilot) 是**工程师 + 运维**（取料、检索、出草稿、建议连接、执行落库）。

---

## 一、前置确认（一次性）
- [ ] LT的知识库 六文件夹就位（00~05，folder_id 见 SKILL.md §2）。
- [ ] `lixiaolai-thinking-truth` skill 已注册可用。
- [ ] 标签体系已建首版：`status/analyzing,pending_review,processed,rejected,deferred,needs_manual_analysis,review` + `type/concept,flow,reference,index` + `src/<>`。（注：`status/inbox` 已弃用——入口不打标签，无 `status/processed` 即待处理，无需 inbox 标签）
- [ ] 新资料进 `00-灵感库` 即可，**不打标签**（无 `status/processed` = 待处理）；管线扫 00 中无 processed 即 inbox。

## 二、日常入站处理 SOP（每份新资料）
**目的**：过六要素框架 → 整合进第二大脑 → 不丢连接、不堆碎片。

### Step 1 · 存料（你）
把文章 / 书 / 灵感 / 链接存进 `00-灵感库`（**不打标签**，无 `status/processed` 即待处理）。
> 在 copilot 里丢给我也行，我会用 `add_knowledge` 帮你持久化进 `00-灵感库` 再跑——但**只聊不落 KB = 没进第二大脑**。

### Step 2 · 触发（你 / cron）
- 手动：对我说"跑第二大脑管线"或一键脚本。
- cron：定时扫 `00-灵感库` 中无 `status/processed` 的项（见 SKILL.md §4[0]）。

### Step 3 · 取料 + 取上下文（脚本，自动）
脚本取正文、搜全库相关旧知。你无需操作。

### Step 4 · 审阅草稿卡（你 · 核心环节）
打开 `05-Skill` 里的"分析草稿卡"（`status/pending_review`）：
- **逐笔记**看概念 / 关系 / 流程三表草稿。
- 对每条关键原子笔记做判断：**留 / 并 / 弃 + 我的立场一句话**。
- 检查 AI 给的**偏见检查**（缺失对立视角？回音室？样本不足？）。
- 看 diff 预览（将创建 N 概念@02、链接 M、移动源至 04-A-Archive、K 项低置信需确认）。

### Step 5 · 决策（你）
- **确认执行** → 脚本去重闸门 → 落库（原子笔记@02、连接、MOC 索引、源移 04-A-Archive 打 processed）。
- **拒绝** → `status/rejected`（零不可逆写）。
- **延迟** → `status/deferred`（cron 跳过，后续提醒）。

### Step 6 · 留痕
运行摘要自动写入 `05-Skill` 日志区（新增概念/链接/移出/拒绝计数）。

## 三、每周 / 双周 Express SOP（防坟场）
**目的**：让第二大脑"出"得来，验证知识真被内化。
1. cron / 手动触发 Express：AI 汇总近 N 天 `status/processed` 落库。
2. 产出"可组合洞察 / 可决策议题"卡，供你审阅。
3. 你挑可落地的 → 转 `01-P-Projects` 行动项，或转文章 / 决策。
4. 看连接密度 / 复用率，决定哪些孤立笔记回炉（`status/review`）或归档（`04-A-Archive`）。

---

## 四、月度维护 SOP
- [ ] 跑**连接密度报表**（孤立笔记占比、最大聚类、复用率）。
- [ ] 标签 prune：合并近义、删除 <3 次使用的标签（全库 ≤50–75 活跃）。
- [ ] 归档：完成的 `01-P-Projects` → `04-A-Archive`；陈旧笔记打 `status/review`。
- [ ] 回顾本 SOP：哪步你总跳过？哪步产出最有用？据此调 MVP 权重。

---

## 五、决策判据（你拍板时的速查）
| 情形 | 建议 |
|---|---|
| 概念可跨源复用、非显然 | **留**（建原子笔记@02） |
| 与已有概念同义异名 | **并**（链接已有，不新建） |
| 一句话事实、无法独立成立 | **弃 / 并入分析卡** |
| AI 给的连接无 evidence | **弃**（schema 已硬过滤，残余人工兜底） |
| 主题旧知 < 阈值 | 标**低置信**，谨慎留用 |
| 你对该议题有强立场 | 在笔记写"我的立场一句话"，压过 AI 默认表述 |

---

## 六、红线（不可逆，务必人确认）
- 任何 `create / move / tag` 不可逆，**确认动作只在你点"执行落库"后发生**。
- 拒绝 / 延迟 = 零不可逆写，放心用。
- 若发现误落库：ima 无删除，只能 `move` 到 `04-A-Archive` 或打 `status/rejected` 隔离，无法清除——这是设计前提，靠去重闸门 + 审阅前置规避。
