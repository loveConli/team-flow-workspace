# 研究报告生成

报告的核心价值不是信息量大，而是基于可靠信息帮读者做出判断。好报告让读者读完后能做决策；差报告要么让读者"知道了很多但不知道该怎么办"，要么更糟——让读者基于不准确的信息做出错误决策。

## 核心规则

**准确性底线**：报告中每一个事实性陈述都必须能追溯到素材文件。无素材支撑的内容不写入报告——发现素材不足时补搜，无法补搜时明确标注"现有资料中未找到相关数据"。数字是准确性最敏感的地方：直接引用原始数据，禁止对原始数据做二次计算后写入（如需推算，标注"据 XX 数据推算"并保留原始数字）。

## 流程速览

```
Step 1  需求理解 → 核心问题清单
          ↓
Step 2  信息收集 → 按问题并行搜索 → 结构化素材文件
        素材质量自检 → 不足则补搜
          ↓
Step 3  大纲规划 → 输出大纲
        ⛔ 确认门（用户确认或明确跳过后才继续）
          ↓
Step 4  逐章撰写 + 整合交付（标题 + 摘要 + 参考来源）
```

## 你的工作方式

不要强制从第一步走起。判断用户当前在哪个阶段，从那里接入：

- 用户只给了一个模糊主题 → 从需求澄清开始
- 用户带着素材来 → 跳过搜索，直接进入大纲规划
- 用户已有一份报告，想改某一章 → 直接进入修改模式
- 用户说"不用确认了直接写" → 尊重用户的节奏，跳过确认门

## Step 1：需求理解与核心问题清单

### 需求澄清

用户给出了明确的研究问题和上下文时，不要反复确认，直接推进。用户只说"帮我写个报告"而没有明确主题时，先追问。识别用户已有的资源（特定文件、知识库、数据来源），这些是优先素材。

### 核心问题清单

将研究主题拆解为需要回答的核心问题清单，这份清单是后续搜索和大纲设计的锚点，拆解完成后直接进入 Step 2。

拆解原则：
- **精准聚焦**：核心问题 ≤ 5 条。问题清单要回应用户的决策需求，不是做百科全书式的全面覆盖
- **合并重叠**：如果两个问题的搜索关键词高度重叠（搜一个基本能覆盖另一个），合并为一个问题
- **互不重叠、完全穷尽**：问题之间不重复，合在一起覆盖主题全貌
- **可搜索**：每个问题足够具体，能直接转化为搜索任务

示例：
```
核心问题（≤ 5 条）：
1. 大模型在教育领域有哪些主要应用场景和典型产品？
2. 实际应用效果如何（有无数据支撑）？
3. 当前面临的主要挑战和风险？
4. 未来发展趋势和机会？
```

## Step 2：信息收集

搜索的目标不是"搜了几轮"，而是"核心问题清单上的每一条是否都有可靠素材支撑"。

### 按问题并行搜索

围绕核心问题清单并行发起搜索。

- **搜索**：根据核心问题设计搜索关键词，尽量并行调用以提高效率。一次搜索可能覆盖多个问题，一个问题也可能需要多角度搜索——按实际情况灵活安排
- **提纯与结构化**：对搜索结果做提纯——筛选有价值的信息，按核心问题归类，每条标注原始来源，写入 workspace 素材文件。这一步的目的是强制筛选和结构化，为后续写作提供清晰的素材索引

### 素材质量自检

读完所有素材文件后，逐条对照核心问题清单自检：

| 检查项 | 标准 |
|--------|------|
| 覆盖度 | 每个核心问题都有素材支撑 |
| 具体度 | 关键论点有具体的数据、案例或引用，而非只有笼统描述 |
| 可靠度 | 重要事实有多个来源佐证，或来自权威来源 |
| 时效性 | 数据的时间节点已标记，没有把过时信息当作现状 |

不满足 → 针对缺口补搜。宁可多搜一轮，也不要带着素材缺口进入写作。

## Step 3：大纲规划

### 设计原则

- **需求驱动**：大纲结构应精准响应用户的研究问题，而非套用通用模板。关键区分维度是：这个报告要帮读者做什么决策？投资决策需要市场规模和竞争格局；产品决策需要功能对比和差异化定位；合规决策需要法条和判例。让结构服务于决策需求。
- **有素材才有章节**：素材文件中没有支撑的章节不应出现。
- **标题有信息量**：避免"分析与讨论"这种空洞标题。标题应传达该章节的核心结论或要回答的问题。
- **逻辑连贯**：只读各章节标题，应该构成一条通顺的论证链。

章节数取决于核心问题清单的结构，而非预设数字。

### 大纲格式

大纲应包含报告标题和章节结构：

```
# [报告标题]

## 一、[章节标题]
### 1.1 [子主题]
### 1.2 [子主题]

## 二、[章节标题]
### 2.1 [子主题]
### 2.2 [子主题]
```

报告标题要简洁、有信息量，体现研究主题和核心发现。章节标题应传达该章节的核心结论或要回答的问题，避免"分析与讨论"这种空洞表述。

### ⛔ 确认门

输出大纲后，等待用户确认再进入撰写阶段。用户可能调整章节顺序、增删章节、修改方向。

**跳过条件**：用户明确表示不需要确认。

## Step 4：撰写

基于素材文件逐章撰写，对于每一章：file_write 第一章到报告文件，后续各章用 file_edit 追加到文件末尾。

### 写作原则

**准确性优先**——内容分三层：
- **素材中的事实**：直接引用，标注来源和时间（如"据 IDC 2025 年报告"），或以括号形式呈现（如"（来源：XX 报告, 2025）"）
- **基于素材的推断**：措辞应体现推断性质（"这表明""由此可见"），让读者区分事实和判断
- **素材中没有的内容**：不编造。补搜或标注缺失

**每章应有判断，不只是罗列**——每个章节应该有明确的结论或判断，不只是罗列事实。但判断必须建立在素材之上。

**信息密度**——深度挖掘素材中的具体细节：数字、案例、时间节点、因果关系。用完整段落组织，一段一论点，避免碎片化短句堆砌。

**篇幅控制**——用户指定了字数/篇幅时，在写作前根据目标篇幅分配各章节的预估字数，写作中控制每章不超出预估。

**交付格式**——Markdown 是报告的最终交付格式，除非用户明确指定了目标文件格式，否则不要转换为 PDF/HTML/DOCX。
