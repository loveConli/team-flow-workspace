# 反馈学习层（L4 Loop · Distill Pipeline）

> 报告引用: §6 反馈学习层（分层处理）/ §6.9 反馈原则（尽早纠偏、信任但验证）/ §6.2 阶段6 发布与结项
> 定位: 回收 CR 评论、issue 对话、验收记录、自恢复日志、人工修正，分层处理：稳定知识→wiki / 反复流程问题→skill / 一次性材料→归档。
> 核心论点: "无此层则系统无状态"——没有反馈学习层，Agent 每次都从零开始，犯过的错误还会再犯。
> 标签: 【来源已核验✅】

## 回收材料的来源

| 来源 | 类型 | 回收时机 | 处理方式 |
|------|------|----------|----------|
| CR 评论 | 代码审查反馈 | CR resolve 后 | 分析 → 归入稳定知识或反复问题 |
| Issue 对话 | 问题跟踪 | Issue 关闭后 | 分析 → 归入稳定知识或反复问题 |
| 验收记录 | 验收验证结果 | 验收通过后 | 分析 → 归入稳定知识或反复问题 |
| 自恢复日志 | 崩溃/错误恢复记录 | 恢复后 | 分析 → 归入反复问题或一次性材料 |
| 人工修正 | 人工介入后的修正 | 修正后 | 分析 → 归入反复问题（防止再次犯错） |
| 观察期日志 | 发布后的监控数据 | 观察期结束后 | 分析 → 归入稳定知识 |

## 分层处理管道（Distill Pipeline）

```
回收材料入池
  │
  ├─ 结项审视（superai-finish 编排）──► 自动化分类 + 人工审查
  │
  ▼ 分类结果
  │
  ├─ 稳定知识 ───────► 写入长期 wiki 仓库（master）
  │   （LLM Wiki、codemap、架构决策、接口契约）
  │   条件: 多个需求验证为稳定、不随需求变化
  │   审批: WAITING_USER（人工确认后写入）
  │
  ├─ 反复流程问题 ───► 更新 skill / prompt / 规则
  │   （CLAUDE.md / AGENTS.md / SDD 模板 / 策展策略）
  │   条件: 同类型错误在 ≥2 个需求中出现
  │   审批: 小型走 CR 确认 / 大型走 CCB/ARB
  │   版本控制: Skill 版本号 + 变更日志
  │
  └─ 一次性材料 ─────► 归档（留在项目记忆仓库，标记 archived）
      （特定需求的临时决策、已废弃的 API 设计、一次性测试数据）
      条件: 仅适用于单个需求、不具复用价值
      生命周期: 保留 90 天后可清理（按团队政策）
```

## 稳定知识 → 长期 wiki 的蒸馏规则

| 知识类型 | 蒸馏位置 | 格式 | 更新频率 | 审批 |
|----------|----------|------|----------|------|
| 架构决策 | `wiki/architecture-decisions/` | ADR (Architecture Decision Record) | 每需求结项审视 | WAITING_USER |
| 业务知识 | `wiki/llm-wiki.md` | Markdown 结构化 | 每需求结项审视 | WAITING_USER |
| 代码地图 | `wiki/codemap.md` | 模块图 + 关键路径说明 | 每需求结项审视 | WAITING_USER |
| 接口契约 | `wiki/interface-contracts.md` | API schema + 消费方列表 | 仅接口变更时 | CCB/ARB |
| 工程规范 | `CLAUDE.md` / `AGENTS.md` | 持久提示层 | 反复验证稳定后 | CR 确认 |

## 反复流程问题 → Skill/Prompt 改进规则

| 问题类型 | 改进目标 | 触发条件 | 改进方式 | 验证 |
|----------|----------|----------|----------|------|
| Skill 输出不一致 | superai-clarify / superai-plan 输出质量差 | ≥2 个需求中输出不符合模板 | 优化 Skill 提示词 + 增加 few-shot 示例 | 下一个需求验证 |
| 上下文策展失效 | Agent 加载错误文件 / 遗漏关键上下文 | ≥2 个需求中上下文不足 | 优化 Retrieve 策略 / 调整 NOTES.md 格式 | 下一个需求验证 |
| 质量门绕过 | pre-push gate 被绕过 / hook 失效 | ≥1 次绕过事件 | 强化 Hook 配置 + CI backstop | 下一个 merge 验证 |
| 成本超标 | 单需求成本 > 基线 1.5 倍 | ≥2 个需求超标 | 优化任务拆分粒度 / 调整 compact 阈值 | 下一个需求验证 |
| 审计未闭合 | idempotency_key 重复 / CI-ID 不一致 | ≥2 个需求未闭合 | 优化 PostToolUse 落盘逻辑 | 下一个需求验证 |

## 一次性材料归档规则

| 材料类型 | 归档位置 | 保留期限 | 清理策略 |
|----------|----------|----------|----------|
| 临时测试数据 | `memory/archive/test-data/` | 30 天 | 自动清理 |
| 废弃设计方案 | `memory/archive/designs/` | 90 天 | 手动审查后清理 |
| 调试日志 | `memory/archive/debug-logs/` | 7 天 | 自动清理 |
| 一次性脚本 | `memory/archive/scripts/` | 90 天 | 手动审查后清理 |

## Distill 触发条件

1. **自动触发**: 状态机 `RELEASING` → `CLOSED` 时，由 `superai-finish` skill 自动触发
2. **人工审查**: superai-finish 生成分类建议 → WAITING_USER 确认 → 执行蒸馏
3. **批量触发**: 每季度批量审视所有未蒸馏材料（防止积压）

```
项目记忆仓库（feature 分支）──┤                                （superai-finish）
                              │                                    │
                              │                                    ├─► 长期 wiki（master）
                              │                                    │    （稳定知识）
                              │                                    │
                              │                                    ├─► skill/prompt 更新

                              └───────────────────────────────────────（audit-log 永久保留）
```
